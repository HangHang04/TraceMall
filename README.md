# TraceMall（优秀毕设版规划）

> 面向《可溯源的水果商城设计与实现》的重构版本。
> 当前阶段仅完成“工程初始化 + 任务规划”，不写业务代码。

## 1. 项目目标

TraceMall 目标是构建一个“可交易 + 可追溯 + 可监管”的水果商城系统，解决传统链路中信息不透明、数据可篡改、消费者难以验证来源的问题。

相对普通毕设，本项目按“优秀毕设”标准提升为：
- 不只做商城功能，而是做“交易链路 + 溯源链路 + 防伪链路”三链协同；
- 不只展示二维码，而是提供“校验规则 + 篡改检测 + 风险告警”；
- 不只完成 CRUD，而是形成“论文可论证”的指标体系与实验设计。

## 2. 研究问题映射（对应开题报告）

5. 系统测试与可行性验证

## 3. 技术路线（重构后的优选方案）

### 3.1 架构分层
- 展示层：用户端商城 + 管理后台
- 业务层：商品、订单、溯源、防伪、监管查询
- 数据层：MySQL（业务数据）+ Redis（缓存）
- 可信层：区块链存证（关键事件哈希上链，业务明细链下）

### 3.2 溯源模型（推荐）
- 链下存明细：种植、采收、分拣、质检、仓储、运输、签收
- 链上存哈希：每次关键事件生成摘要并锚定，保证不可篡改
- 二维码承载：traceId + 批次 + 校验字段（签名/摘要）

### 3.3 防伪校验核心
- 规则1：二维码格式合法性校验
- 规则2：签名/摘要一致性校验
- 规则3：上链锚点一致性校验
- 规则4：扫描频次与地理异常检测（风控）

## 6. 毕设论文“优秀化”设计要点

1. **理论-实现闭环**：每个理论点都在系统中有可验证实现。
2. **可量化指标**：
   - 溯源完整率
   - 篡改检出率
   - 平均查询时延
   - 异常扫描识别率
3. **可复现实验**：给出固定数据集、固定流程、固定指标计算方法。
4. **工程规范**：统一接口规范、迁移脚本、日志审计、异常码体系。
