# TraceMall 项目介绍与使用说明

## 1. 项目简介

TraceMall 是一个面向水果供应链场景的“可交易、可追溯、可验真、可监管”系统。  
它不是单纯的电商平台，而是把商城交易链路、批次溯源链路、二维码验真链路和监管风控链路整合在一起。

项目的核心目标是解决以下问题：

- 消费者买到水果后，无法确认来源是否真实；
- 商家即使提供二维码，也可能只是静态展示，无法校验是否被篡改；
- 监管方缺少统一的异常沉淀与查询入口；
- 传统系统很难同时兼顾“业务效率”和“可信追溯”。

## 2. 项目使用了什么技术

### 前端技术

- Vue 3：构建页面与组件；
- Vite：前端开发与构建工具；
- Vue Router：路由管理；
- Pinia：登录态和购物车状态管理；
- Axios：接口请求封装；
- ECharts：商家端和监管端的数据可视化；
- `html5-qrcode`：摄像头扫码与二维码图片识别；
- `qrcode`：二维码生成与下载。

### 后端技术

- Spring Boot：整体后端框架；
- Spring Security：登录认证和角色权限控制；
- Jakarta Validation：请求参数校验；
- MyBatis：数据库访问；
- Flyway：数据库建表与演示数据初始化；
- MySQL：业务数据存储；
- Redis 依赖已接入：为后续缓存能力预留基础；
- Springdoc OpenAPI：接口文档能力；
- JUnit + Mockito：核心逻辑测试。

## 3. 系统角色与主要功能

### 3.1 消费者端

主要功能：

- 浏览在售水果；
- 按分类和关键词筛选商品；
- 查看商品详情；
- 将商品加入购物车；
- 创建订单并模拟支付；
- 通过手动输入或扫码方式进行二维码验真；
- 查看最近验真记录；
- 查看对应批次的溯源事件链。

### 3.2 商家端

主要功能：

- 新增水果商品；
- 创建水果批次；
- 系统自动生成 `traceId` 和签名；
- 生成可下载的二维码；
- 补录溯源事件，例如采收、质检等；
- 查看商品结构和价格分布。

### 3.3 监管端

主要功能：

- 查看风险告警列表；
- 查看审计日志；
- 观察风险等级分布；
- 观察主要访问模块；
- 从异常二维码追溯到具体批次和业务操作。

## 4. 项目是如何实现的

## 4.1 整体架构

项目采用前后端分离结构：

- `web/`：前端界面和交互逻辑；
- `server/`：后端业务逻辑、权限控制和数据访问。

前端通过 Axios 调用后端 REST API，后端通过 MyBatis 访问 MySQL 数据库。  
在可信设计上，关键事件会生成哈希，并通过锚点网关进行“上链校验”模拟。

## 4.2 溯源实现方式

溯源模块主要分为两层：

### 链下业务明细

数据库中保存：

- 水果信息；
- 批次信息；
- 库存；
- 溯源事件；
- 订单信息；
- 扫码日志；
- 风险告警；
- 审计日志。

### 可信校验层

后端对关键事件和二维码进行可信校验：

- 扫码时检查 `traceId` 格式是否合法；
- 根据 `traceId + batchNo + signKey` 校验签名是否一致；
- 校验质量事件对应的锚点是否匹配；
- 统计短时间高频扫码和异地扫码行为，判断是否存在风险。

## 4.3 二维码扫码溯源是如何实现的

本项目的二维码不是简单图片，而是和验真流程绑定的“业务入口”。

实现方式如下：

1. 商家创建批次时，后端生成 `traceId` 和 `signature`；
2. 前端将这两个参数拼成公共验真链接；
3. 使用 `qrcode` 生成二维码并支持下载；
4. 消费者在扫码页使用摄像头或上传图片识别二维码；
5. 前端解析二维码内容，自动回填 `traceId` 和 `signature`；
6. 调用 `/api/trace/verify` 完成验真；
7. 如果验真成功，再调用 `/api/trace/{traceId}` 拉取完整溯源事件链。

这样就形成了“生成二维码 -> 扫码 -> 自动验真 -> 查看溯源详情”的完整闭环。

## 6. 如何运行项目

### 6.1 启动后端

进入 `server/` 目录后执行：

```bash
./mvnw spring-boot:run
```

Windows 下可执行：

```bash
mvnw.cmd spring-boot:run
```

默认数据库配置：

- Host：`localhost`
- Port：`3308`
- Database：`tracemall`
- Username：`root`
- Password：`123456`

如果数据库中没有表结构，Flyway 会自动执行迁移脚本并写入演示数据。

### 6.2 启动前端

进入 `web/` 目录后执行：

```bash
npm install
npm run dev
```

默认情况下，前端会请求：

```bash
http://localhost:18081
```

如果需要修改后端地址，可以通过环境变量 `VITE_API_BASE_URL` 覆盖。

## 7. 如何使用系统

### 7.1 登录

演示账号如下：

- 消费者：`consumer01 / 123456`
- 商家：`merchant01 / 123456`
- 监管方：`regulator01 / 123456`

### 7.2 消费者使用流程

1. 登录消费者账号；
2. 在商城页浏览商品并加入购物车；
3. 查看商品详情与溯源事件；
4. 在扫码页或首页打开摄像头扫描二维码；
5. 查看验真结果、风险等级和批次摘要；
6. 下单后在订单页模拟支付。

### 7.3 商家使用流程

1. 登录商家账号；
2. 新增水果商品；
3. 创建批次；
4. 系统自动生成 `traceId`、签名和二维码；
5. 下载二维码并用于展示或贴码；
6. 继续录入质检、仓储等溯源事件。

### 7.4 监管方使用流程

1. 登录监管账号；
2. 查看风险告警；
3. 查看高风险二维码与异常类型；
4. 查看审计日志；
5. 根据 traceId 继续追查异常来源。

## 8. 项目亮点

这个项目的亮点主要体现在四点：

1. 不是单独做商城，而是做“交易 + 溯源 + 验真 + 监管”联动；
2. 二维码不是静态展示，而是能真正进入验真流程；
3. 有异常沉淀机制，扫码结果会进入风险告警和审计日志；
4. 结构清晰，前后端分离，便于继续扩展为更完整的供应链可信系统。
